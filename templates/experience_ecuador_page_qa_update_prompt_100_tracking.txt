LANGUAGE SWITCH STANDARD
Every bilingual page must have the raw EN/ES language switch immediately after the site header container and before hero/main content.

English page pattern:
<div id="siteHeader" data-current-lang="en"></div>
<nav class="rawLangLinks" aria-label="Language switch">
  <a href="FULL_EN_URL" lang="en" hreflang="en" aria-current="page" data-analytics-event="language_switch_click" data-analytics-label="English" data-analytics-location="language_switch" data-analytics-page-type="PAGE_TYPE" data-analytics-target-language="en">English</a>
  <a href="FULL_ES_URL" lang="es" hreflang="es" data-analytics-event="language_switch_click" data-analytics-label="Español" data-analytics-location="language_switch" data-analytics-page-type="PAGE_TYPE" data-analytics-target-language="es">Español</a>
</nav>

Spanish page pattern:
<div id="siteHeader" data-current-lang="es"></div>
<nav class="rawLangLinks" aria-label="Selector de idioma">
  <a href="FULL_EN_URL" lang="en" hreflang="en" data-analytics-event="language_switch_click" data-analytics-label="English" data-analytics-location="language_switch" data-analytics-page-type="PAGE_TYPE" data-analytics-target-language="en">English</a>
  <a href="FULL_ES_URL" lang="es" hreflang="es" aria-current="page" data-analytics-event="language_switch_click" data-analytics-label="Español" data-analytics-location="language_switch" data-analytics-page-type="PAGE_TYPE" data-analytics-target-language="es">Español</a>
</nav>

Language switch rules:
- Keep class exactly: rawLangLinks
- Use real raw HTML anchor tags
- Do not rely only on JavaScript-injected language links
- Use hreflang on both links
- Use aria-current="page" only on the active language
- Add language_switch_click analytics to both links
- Keep the switch directly under #siteHeader
- Do not add page-level switch CSS unless truly necessary

HEADER AND FOOTER STANDARD
Every page must include:
<div id="siteHeader" data-current-lang="en"></div>
or
<div id="siteHeader" data-current-lang="es"></div>

And:
<div id="siteFooter"></div>

The footer/header include loader must be present exactly once:
<script>
  (function(){
    async function inject(id, url){
      var el = document.getElementById(id);
      if(!el) return;
      var res = await fetch(url, { cache: "no-store" });
      el.innerHTML = await res.text();
    }
    Promise.all([
      inject("siteHeader", "/assets/includes/header.html"),
      inject("siteFooter", "/assets/includes/footer.html")
    ]).then(function(){
      if (!document.querySelector('script[src="/assets/js/site.js"]')) {
        var s = document.createElement("script");
        s.src = "/assets/js/site.js";
        document.body.appendChild(s);
      }
    });
  })();
</script>

Rules:
- Do not use header-es.html or footer-es.html
- Both EN and ES pages use the same /assets/includes/header.html and /assets/includes/footer.html
- Do not include a separate simple <script src="/assets/js/site.js"></script> if the guarded loader is already used
- Do not duplicate the include loader
- The loader must remain valid JavaScript

URL, HREFLANG, CANONICAL QA
For both pages:
- Canonical must match that page's actual live URL
- EN alternate must point to EN URL

- x-default should usually point to EN URL
- og:url must match canonical
- Schema URL and breadcrumb URLs must match the correct paths
- No singular/plural path mismatch, for example /region/ vs /regions/
- Do not change English image URLs on Spanish pages unless the actual file path is different. Spanish pages normally reuse the same image asset paths as English pages.
