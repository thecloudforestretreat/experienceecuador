BLOG / GUIDE PAGE TEMPLATE V6
EXPERIENCE ECUADOR
PRODUCTION TEMPLATE

PAGE TYPE
- This template is for BLOG / GUIDE PAGES for ExperienceEcuador.com.
- Use for evergreen travel guides, comparison posts, itinerary posts, packing posts, city guides, and things-to-do posts.
- Output must always be a COMPLETE, FULL, DROP-IN HTML FILE.
- Never output partial sections.
- Never output summaries instead of files.
- Deliver as downloadable .txt files only.

==================================================
CORE PURPOSE
==================================================
This template exists to ensure that all remaining Experience Ecuador blog pages:
- follow the same premium visual rhythm
- follow the same SEO logic
- follow the same bilingual discovery logic
- follow the same internal-linking logic
- feel like they belong to the same site system
- are close to live-ready on the first pass

This is a PRODUCTION WORKFLOW TEMPLATE, not a loose content outline.

==================================================
APPROVED REFERENCE PATTERN
==================================================
Use the supplied English / Spanish "Best Things to Do in Ecuador" pages as the current blog guide reference.

The reference pattern includes:
- complete head metadata
- canonical and hreflang links
- OG and Twitter tags
- TravelGuide or relevant primary schema
- FAQPage schema when FAQ is present
- BreadcrumbList schema
- shared CSS only
- image hero with visible EN / ES links
- quick decision cards
- core comparison / decision cards
- practical planning logic cards
- related destination / experience cards
- related collection cards
- FAQ cards
- final CTA band
- siteHeader and siteFooter mounts
- site.js plus the approved lightweight include bootstrap

==================================================
MANDATORY SEO / SOCIAL / SCHEMA PACKAGE
==================================================
Every page must explicitly produce and apply these fields:

1. Title (SEO optimized)
   - Max 60 characters.
   - Format: [Primary Keyword] | [Value]
   - Must include "|".
   - Use in <title>.

2. Meta Description
   - 140 to 160 characters.
   - Use in <meta name="description">.

3. H1 (aligned with title)
   - Must align with title.
   - Usually simpler than the title.
   - Use in the hero <h1>.

4. New OG Title
   - Same as title.
   - Use in og:title and twitter:title.

5. New OG Description
   - Same as meta description.
   - Use in og:description and twitter:description.

6. New Schema Name
   - Title with the pipe removed.
   - Example: "Best Things to Do in Ecuador | Smart Guide" becomes "Best Things to Do in Ecuador Smart Guide".
   - Use in JSON-LD "name".

7. New Schema Description
   - Same as meta description.
   - Use in JSON-LD "description".

WORKFLOW BEFORE WRITING
==================================================
Before drafting the page, determine and lock the following:

1. PAGE INTENT
Choose one primary intent:
- Guide
- Comparison
- Itinerary
- Packing
- City Guide
- Things to Do

2. PRIMARY KEYWORD
Choose 1 primary keyword.

3. SECONDARY KEYWORDS
Choose 3 secondary keywords.

4. SEARCH INTENT
Clarify whether the user is trying to:
- compare options
- choose a region
- build a route
- plan logistics
- avoid mistakes
- understand suitability by traveler type

5. URLS
Lock:
- canonical URL
- English URL
- Spanish URL
- x-default URL

6. SEO / SOCIAL / SCHEMA PACKAGE
Lock:
- Title (SEO optimized)
- Meta Description
- H1
- New OG Title
- New OG Description
- New Schema Name
- New Schema Description

7. CARD RHYTHM
Choose where cards should appear:
- 4-card summary section
- 2-card or 4-card comparison section
- 3-card related destination section
- 2 to 4-card related collection section

8. CTA PATH
Choose the two strongest CTA targets based on page intent.

Do NOT begin the full page until those eight inputs are clear.

==================================================
1. HERO
==================================================
Required:
- H1
- 1 short supporting sentence
- Optional brand line or kicker
- 1 hero image
- Visible EN / ES crawlable language links in raw HTML
- 1 to 2 CTA buttons
- Optional hero pills when they clarify categories, regions, seasons, or trip styles

Hero rules:
- Keep concise.
- No long intro paragraphs in hero.
- H1 must align with the SEO title but read slightly cleaner.
- Supporting sentence should reinforce search intent and value.
- Hero must immediately clarify what the page helps the user decide.

Hero image rule:
- Use 1 strong hero image.
- If no image is available, use the approved placeholder:
  https://experienceecuador.com/EE-OG-Image-1.jpg

Visible bilingual discovery rule:
- EN / ES links must exist in raw HTML.
- They must be crawlable.
- They must not be the only language discovery method; hreflang is still required.
- They should be integrated cleanly, usually in the hero.

==================================================
2. INTRO (HOOK + CONTEXT)
==================================================
Required:
- 2 to 3 short paragraphs.
- Answer the intent immediately.
- Clarify what the post will help the reader decide, compare, plan, or avoid.
- Set expectations for what comes next.

Rules:
- Answer first, explain second.
- No fluff.
- No generic travel-blog filler.
- First paragraph should target the main search intent directly.
- Include natural internal links where appropriate.
- Intro should feel strategic, not literary.

==================================================
3. QUICK SUMMARY / KEY TAKEAWAYS
==================================================
Required:
- 4 to 6 bullets OR 4 short cards.
- Fast answers for skimmers.
- Must be useful, not repetitive.

Typical content:
- Best for
- Best route fit
- Main tradeoff
- Who it suits
- Common mistake to avoid
- Best next step

Rules:
- This section should help a skimmer understand the page in under 20 seconds.
- If a card version is used, cards must still be informative, not decorative.
- Do not repeat the hero copy.
- This section should be tighter than the main content.

==================================================
4. CORE COMPARISON / PRIMARY DECISION SECTION
==================================================
Required:
- This is the strongest section after the intro.
- Must be presented as real cards or real comparison blocks, not plain generic text stacks.
- Must help the reader make a decision.

For comparison, region, guide, and things-to-do pages:
- This section is mandatory.

Recommended formats:
- 2-card comparison grid for head-to-head choices
- 4-card region or category grid
- Card-led choice architecture with image + title + utility + CTA

Every image card in this section should include:
- image
- name
- one-line utility value
- short explanatory line
- CTA link

Rules:
- This section is where the page earns its usefulness.
- It must feel premium and highly scannable.
- It should reflect the approved destination card language.
- For region pages and route pages, enforce the approved Experience Ecuador card rhythm.
- For Ecuador-wide pages, preserve correct order when applicable:
  - Galapagos
  - Coast
  - Andes
  - Amazon
- Do not use plain text columns pretending to be cards.

==================================================
5. MAIN CONTENT SECTIONS
==================================================
Required:
- Use H2 and H3 hierarchy.
- Short paragraphs only.
- Lists and bullets preferred where useful.
- Clear subtopics.
- Must satisfy real search intent.

Rules:
- H2s must be purposeful and keyword-aware.
- H3s should clarify comparisons, planning logic, or sub-decisions.
- Keep paragraphs to 2 to 4 lines max when possible.
- Avoid vague generic statements.
- Use practical decision language.
- Every section must help the user decide, compare, plan, or avoid a mistake.

Examples of suitable section types:
- What this page helps you decide
- Best options by traveler type
- Region-by-region comparison
- Common mistakes
- Route fit
- Packing, budget, time, logistics, or suitability
- How to choose between options
- What to do first
- Suggested planning logic
- Best route shapes
- Best region combinations
- When one option fits better than another

==================================================
6. INTERNAL LINKING (INLINE)
==================================================
Required:
- Links must appear naturally inside the article body.
- Do not isolate all links in one footer-like block.
- Use descriptive anchor text.

Link naturally to:
- Destination pages
- Experience pages
- Collection pages
- Trip Builder
- Related guides
- Relevant comparison pages
- Relevant itinerary pages

English pages must naturally include:
- /trip-builder/
- /best-places-to-visit-in-ecuador/
- /where-to-stay-in-ecuador/

Spanish pages must naturally include:
- /es/planificador-de-viajes/
- /es/mejores-lugares-para-visitar-ecuador/
- /es/donde-alojarse-ecuador/

Spanish rule:
- Use ONLY sitemap-confirmed Spanish URLs.
- Never invent Spanish slugs.
- Never manually translate a URL unless confirmed.

Internal linking workflow rule:
- Minimum 3 required ecosystem links per page.
- Minimum 2 additional context-relevant links per page.
- Links must serve user intent, not just SEO.

==================================================
7. VISUAL BREAK SECTIONS (OPTIONAL)
==================================================
Allowed:
- Highlight box
- Quote block
- Comparison block
- Image block
- Pull-quote
- Checklist block
- Recommendation band

Use:
- Every 2 to 3 sections if the page is long.
- To break fatigue and improve scanability.

Rules:
- Must stay lightweight.
- No page-level CSS.
- No inline component JS.
- No decorative filler blocks with no informational value.
- Must contribute either clarity, pacing, or conversion.

==================================================
8. RELATED DESTINATIONS / EXPERIENCES
==================================================
Required:
- 3 to 6 cards.
- Must help users go deeper.
- Must be relevant to the article intent.

Each card should include:
- image
- name
- short why-it-matters line
- CTA link

Rules:
- Link deeper into the ecosystem.
- Use only valid URLs.
- Use placeholder image if no valid image exists.
- Prefer 3-card rhythm for most pages.
- Keep cards visually consistent with approved site language.

==================================================
9. RELATED COLLECTIONS
==================================================
Required:
- 2 to 4 links or cards.
- Must point to relevant high-level pages.

Typical links:
- Best Places to Visit in Ecuador
- Where to Stay in Ecuador
- Ecuador Private Tours
- Ecuador Cloud Forest Lodges
- Ecuador Amazon Lodges
- Ecuador Luxury Travel
- Ecuador Family Vacations
- Coast / Andes / Galapagos / Amazon guides

Rules:
- Should feel lighter than the main comparison section.
- Must still be useful, not filler.
- Prioritize high-level discovery pages.

==================================================
10. FAQ
==================================================
Required:
- 4 to 6 questions only.
- Never exceed 6.
- Must target real long-tail search intent.
- Must support FAQ schema.

Rules:
- Questions must be practical and search-aligned.
- Answers should be concise but useful.
- Do not add filler FAQs.
- FAQs should support ranking and decision-making.
- Visible FAQ content must match FAQPage schema content.

==================================================
11. FINAL CTA
==================================================
Required:
- Headline
- 1 supporting line
- 2 CTA buttons

Recommended CTA targets:
- Trip Builder
- Related collections
- Route recommendation page
- Contact / inquiry page if appropriate

Rules:
- CTA must feel like the logical next step.
- CTA should reflect user intent on that page.
- Do not use vague CTA language.

==================================================
SEO REQUIREMENTS
==================================================
TITLE
- Max 60 characters.
- Format: [Primary Keyword] | [Value]
- Must be ranking-oriented and CTR-aware.
- Avoid generic wording.
- Must be keyword-first.
- Must include "|".

META DESCRIPTION
- 140 to 160 characters.
- Must be high CTR.
- Must include specific benefits.
- Must match real intent.
- Avoid vague filler.
- Must be written for clicks, not just keywords.

H1
- Must align with title.
- Slightly simplified for readability.
- Must not duplicate title word-for-word unless clearly justified.

OG / TWITTER
- New OG Title must equal Title.
- New OG Description must equal Meta Description.
- Twitter title must equal Title.
- Twitter description must equal Meta Description.
- Must include the approved OG image when no custom image exists.

CANONICAL
- Required.

HREFLANG
- Required:
  - en
  - es
  - x-default

VISIBLE BILINGUAL DISCOVERY
- Every page must have crawlable EN / ES links in raw HTML.
- These links must be visible in source, not only injected later through navigation JS.
- Hreflang is required, but must not be the only bilingual discovery method.

SCHEMA (JSON-LD)
Use the correct type depending on page intent:
- TravelGuide for informational guide pages
- TouristTrip for itinerary / trip recommendation pages
- Article for comparison / editorial pages when more appropriate

Always include:
- @context
- @graph
- primary schema object
- name
- description
- url
- inLanguage
- mainEntityOfPage
- publisher
- author
- image
- BreadcrumbList

If FAQ exists:
- Also include FAQPage.

Schema workflow rule:
- New Schema Name = SEO title with the pipe removed.
- New Schema Description = meta description.
- Schema language must match the page language.
- Breadcrumb language must match the page language.

==================================================
KEYWORD STRATEGY
==================================================
Every page must be built around:
- 1 primary keyword
- 3 secondary keywords

Rules:
- Keywords must match real intent.
- No keyword stuffing.
- Use naturally in:
  - title
  - meta
  - H1
  - intro
  - H2s
  - FAQ
  - anchor text where appropriate

==================================================
LANGUAGE RULES
==================================================
ENGLISH
- Clean
- Strategic
- Helpful
- No fluff
- No generic travel-blog tone.

SPANISH
- Natural LATAM / South American Spanish.
- Not literal translation.
- Proper accents in visible text.
- URLs remain ASCII-safe.
- Use only confirmed Spanish URLs from sitemap.
- All visible Spanish text must read naturally in Spanish.
- No mixed English labels or mixed English body text.

==================================================
IMAGE RULES
==================================================
- Hero: 1 image required.
- Additional images: optional.
- Keep lightweight for performance.
- Never leave blank image areas.
- Never invent missing image paths.
- Use placeholder only when needed:
  https://experienceecuador.com/EE-OG-Image-1.jpg

OG IMAGE RULE
- Default OG image:
  https://experienceecuador.com/EE-OG-Image-1.jpg
- Apply to:
  - og:image
  - og:image:secure_url
  - twitter:image
- Include width 1200 and height 630 unless a custom image has different confirmed dimensions.
