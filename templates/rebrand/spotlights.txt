SPOTLIGHTS TEMPLATE - SEO UPDATED

PURPOSE
The Spotlights section is designed to showcase timely, seasonal, or noteworthy events and moments across Ecuador.

It is NOT a blog.
It is NOT evergreen content.

It should:
- highlight what is happening now or what is worth knowing now
- increase engagement and return visits
- support SEO freshness signals
- drive users into regions, experiences, guides, recommendations, and planning pages

PAGE TYPES
1. Spotlights Hub (/spotlights and /es/destacados)
2. Future individual spotlight pages for major events

For now:
- Focus on the hub page only.
- Preserve layout symmetry.
- If a section uses 3 columns, keep complete rows of 3 cards only.
- Do not add orphan cards or empty visual gaps.

REQUIRED SEO FIELDS
Every Spotlights page must include:
- Title: SEO optimized.
- Meta Description: unique, click-worthy, and aligned with the page language.
- H1: aligned with the title.
- New OG Title: exactly the same as the title.
- New OG Description: exactly the same as the meta description.
- New Schema Name: title without the pipe character.
- New Schema Description: exactly the same as the meta description.

BILINGUAL DISCOVERY
Every page must include:
- canonical URL
- hreflang en
- hreflang es
- hreflang x-default
- crawlable raw-source EN/ES links in the HTML body

Important:
- Hreflang is required, but it must not be the only bilingual discovery method.
- Do not rely only on JavaScript-injected navigation for English/Spanish discovery.

STRUCTURED DATA
Use JSON-LD on every hub page:
- WebPage
- BreadcrumbList
- ItemList for the featured spotlights

Schema rules:
- WebPage name must be the title without "|".
- WebPage description must exactly match the meta description.
- ItemList entries should use stable names, positions, and URLs or fragment URLs for featured spotlight items.
- JSON-LD must parse cleanly.

SECTION ORDER - HUB PAGE
1. Raw language switch links
2. Hero
3. Intro / short supporting copy
4. Featured Spotlights carousel or grid
5. Latest Spotlights / supporting cards
6. Related planning and internal links
7. Trip Builder CTA
8. Final CTA or footer

HERO
Purpose:
- Introduce the concept of Spotlights.

Content:
- H1
- short supporting paragraph

Example H1:
Ecuador Travel Spotlights Events & Seasonal Highlights

Keep compact. No oversized hero.

FEATURED SPOTLIGHTS
Purpose:
- Highlight top priority seasonal items.

Content:
- 2 to 4 priority items when possible.
- If using a carousel, keep the controls accessible and keep slide count aligned with dots.

Each featured item:
- image
- title
- short description
- region tag
- experience tag
- timing window
- key planning details
- CTA links

Examples:
- Guayacanes bloom in Loja
- Carnival in Ecuador
- wildlife timing windows
- Quito or regional festivals
- Amazon or Galapagos seasonal highlights

INTERNAL LINKING
Each spotlight should connect to:
- a region page
- an experience page
- possibly a guide page
- planning or recommendations when relevant

Hub pages should include crawlable internal links to:
- Regions
- Experiences
- Best Time to Visit Ecuador
- Ecuador Travel Guide
- Recommendations
- Trip Builder / Planificador

CONVERSION REQUIREMENTS
Include CTAs to:
- regions
- experiences
- trip builder
- recommendations when relevant

IMAGE RULES
- Use strong, relevant visuals.
- Avoid generic stock.
- Each spotlight should feel unique.
- OG/Twitter images should use a relevant page image, not a generic fallback, unless no page image exists.

SPACING RULES
- no empty gaps
- tight grid alignment
- consistent spacing
- no card rows with one leftover card on desktop

MOBILE-FIRST RULES
- stacked cards
- simple grids
- readable text
- no overlapping controls

DESKTOP RULES
- 2 to 4 column grid depending on content count
- balanced layout
- if using 3 columns, use complete rows of 3

CONTENT TONE
- timely
- engaging
- concise
- useful

DESIGN PRINCIPLE
Spotlights should feel like:
- a live travel feed
- curated insights
- seasonal intelligence

Not:
- a blog list
- static filler
- a generic archive

VALIDATION CHECKLIST
Before publishing:
- title equals OG title and Twitter title
- meta description equals OG description and Twitter description
- schema name does not contain "|"
- schema description equals meta description
- canonical and hreflang URLs are correct
- raw EN/ES links exist in source HTML
- JSON-LD parses cleanly
- no empty href values
- no placeholder image names like EE-OG when a page image exists
- no TODO, FIXME, undefined, or broken typo strings
- layout keeps complete card rows
- page ends with valid closing body and html tags
