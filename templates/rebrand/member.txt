EXPERIENCE ECUADOR MEMBER PAGE PROMPT

Use this prompt to generate full, ready-to-publish member profile pages for Experience Ecuador partners, hotels, lodges, tour operators, restaurants, guides, and experience providers.

The output must be a complete HTML file, not a partial section. It must include the full document structure, complete metadata, crawlable bilingual links, schema, header/footer mounts, content sections, FAQ, and final CTA.

PRIMARY GOAL

Create a polished, conversion-focused, SEO-maximized member page that can rank for branded and location/category intent while helping users understand why the member is worth contacting or booking.

The page must feel like a real Experience Ecuador guide page, not a thin directory listing.

The page must also function as a standalone acquisition and analytics landing page for the service Experience Ecuador provides: helping travelers discover, compare, contact, and book trusted Ecuador travel businesses. Do not reduce member pages into short profile pages just because metadata and schema are present.

Preserve the strategic purpose of the page:

- Capture organic search demand for the member, destination, category, and experience type
- Explain how the member fits into Ecuador trip planning
- Provide enough crawlable content for Google to understand the page independently
- Provide enough decision support for travelers to click, contact, or continue planning
- Capture useful Google Analytics events for listing views, CTA clicks, outbound clicks, language clicks, and planning clicks
- Support Experience Ecuador's broader service model through internal links to trip planning, destination guides, lodging guides, recommendations, and related experiences

---

Before generating the page, collect or infer:

- Business / member name
- English URL slug
- Spanish URL slug
- Language of this page: EN or ES
- Page title target
- Business category

- Region: Galapagos, Coast, Andes, or Amazon

If some business details are missing, do not invent precise claims such as prices, certifications, awards, exact schedules, or review counts. Use careful language and clear placeholders only where needed.

Generate one complete `.html` page per language.

The file must include:

- Full `<!DOCTYPE html>`

- Complete `<head>`

- Header mount
- Main content
- Footer mount

Do not output a partial page.
Do not rely on JavaScript to create SEO-critical metadata, schema, H1, canonical, hreflang, or bilingual source links.
Do not shrink the page into a short or compressed version.
Do not remove analytics instrumentation, rich section structure, internal links, carousel logic, or conversion tracking when generating final member files.

Preferred final member page depth:

- At least 450 lines when formatted readably, unless the existing site template is intentionally shorter
- At least 9 visible content sections
- At least 6 crawlable internal links
- At least 3 member-specific images when available
- At least 4 FAQ items
- Dedicated analytics/event tracking script
- Dedicated carousel/gallery script if the page uses image slides

MAX SEO REQUIREMENTS

Every member page must be optimized as close to a 10/10 technical and content SEO baseline as possible.

Include all of the following exactly:

1. Title (SEO optimized)
   - Must be unique
   - Must include the business name and primary location/category when useful
   - Must include a `|` separator when appropriate
   - Ideal length: 45-60 characters
   - Example: `Mashpi Lodge Ecuador | Cloud Forest Hotel`

2. Meta Description
   - Must be unique
   - Must describe the business, location, value, and booking/search intent
   - Ideal length: 140-160 characters
   - No keyword stuffing

3. H1
   - Must align with the title
   - Can be identical to the title without the brand separator, or a natural page-facing version
   - Must appear in raw HTML
   - Only one H1 per page

4. New OG Title
   - Must be exactly the same text as the `<title>`

5. New OG Description
   - Must be exactly the same text as the meta description

6. New Schema Name
   - Must be the title text with the `|` removed
   - Example:
     - Title: `Mashpi Lodge Ecuador | Cloud Forest Hotel`
     - Schema name: `Mashpi Lodge Ecuador Cloud Forest Hotel`

7. New Schema Description
   - Must be exactly the same text as the meta description

Also include:

- Canonical URL
- Hreflang EN
- Hreflang ES
- Hreflang x-default
- `meta name="robots" content="index,follow"`
- Open Graph URL
- Open Graph type
- Open Graph image
- Open Graph image alt
- Open Graph locale
- Open Graph alternate locale
- Twitter card
- Twitter title, same as title
- Twitter description, same as meta description
- Twitter image
- Twitter image alt

BILINGUAL DISCOVERY REQUIREMENT

Every page must have crawlable EN/ES links available in the raw source HTML.

Hreflang is required, but hreflang must not be the only bilingual discovery method.

Therefore, every member page must include:

1. Hreflang tags in the `<head>`
2. A visible or visually modest language switcher in raw HTML near the top or bottom of the page
3. A contextual bilingual link in raw HTML, such as:
   - English page links to Spanish version: `Ver esta página en español`
   - Spanish page links to English version: `View this page in English`

The bilingual links must be standard `<a href="...">` links in the HTML source.
Do not inject these links only through JavaScript.
Do not hide them with `display:none`.

Example:

```html
<nav class="languageSwitch" aria-label="Language options">
  <a href="/member-slug/">English</a>
  <a href="/es/member-slug/">Español</a>
</nav>
```
