UTILITY / SUPPORT TEMPLATE - SEO UPDATED

PURPOSE
Utility / Support pages are not always primary SEO drivers, but they are critical for:
- trust
- conversions
- user confidence
- legal compliance
- reducing friction
- internal linking support

These pages support the Experience Ecuador ecosystem.

They include:
- About
- FAQ
- Contact
- Transportation
- Privacy Policy
- Terms
- Partners
- Join / Become a Member

CORE UX GOALS
1. Remove user doubts
2. Provide clear answers quickly
3. Build trust
4. Support conversion indirectly
5. Keep layout clean and distraction-free

DESIGN PRINCIPLE
These pages should feel:
- clean
- simple
- direct
- easy to scan

Not:
- overly designed
- cluttered
- marketing-heavy

COMMON STRUCTURE
1. Raw language switch links
2. Hero, minimal
3. Page content, structured blocks
4. Internal link support row or CTA
5. Footer

REQUIRED SEO FIELDS
Every utility/support page must include:
- Title: SEO optimized.
- Meta Description: unique and aligned with the page language.
- H1: aligned with the title.
- New OG Title: exactly the same as the title.
- New OG Description: exactly the same as the meta description.
- New Schema Name: title without the pipe character.
- New Schema Description: exactly the same as the meta description.

BILINGUAL DISCOVERY
Every page must include:
- canonical URL
- hreflang en
- hreflang es
- hreflang x-default
- crawlable raw-source EN/ES links in the HTML body

Important:
- Hreflang is required, but it must not be the only bilingual discovery method.
- Do not rely only on JavaScript-injected navigation for English/Spanish discovery.

STRUCTURED DATA
Use JSON-LD where appropriate.

Default utility/support schema:
- WebPage
- BreadcrumbList

Page-specific schema:
- About: add Organization
- FAQ: add FAQPage
- Contact: add ContactPage and Organization if useful
- Transportation: add WebPage with rich about/mentions
- Terms / Privacy: keep simple WebPage and BreadcrumbList
- Join / Partners: add Organization and/or Service where appropriate

Schema rules:
- WebPage name must be the title without "|".
- WebPage description must exactly match the meta description.
- JSON-LD must parse cleanly.

HERO
Purpose:
- Establish page purpose quickly.

Content:
- H1
- 1 short sentence

Rules:
- compact
- no oversized hero
- no wasted space

PAGE CONTENT STRUCTURE
This varies by page type.

ABOUT PAGE
Structure:
- short mission paragraph
- what Experience Ecuador is building
- who it helps
- what users can expect next
- internal links to regions, recommendations, and trip builder

FAQ PAGE
Structure:
- grouped questions by category

Categories:
- Planning
- Regions
- Experiences
- Logistics

Each item:
- question
- short answer

SEO:
- strong FAQPage schema opportunity

CONTACT PAGE
Structure:
- short intro
- contact methods
- response expectations
- optional WhatsApp or messaging CTA

TRANSPORTATION PAGE
Structure:
- overview
- flights
- private transport
- buses
- internal travel tips
- internal links to regions

PRIVACY POLICY / TERMS
Structure:
- simple legal layout
- readable sections
- no design distractions

PARTNERS PAGE
Structure:
- intro
- partner cards or logos
- short descriptions
- links to member pages where relevant

JOIN / BECOME A MEMBER
Structure:
- value proposition
- benefits
- who it is for
- how it works
- CTA button

INTERNAL LINKING
Each utility/support page should include crawlable links where relevant to:
- Regions
- Experiences
- Recommendations
- Trip Builder / Planificador
- Contact
- FAQ

For About pages, include a balanced 3-card row:
- Regions
- Recommendations
- Trip Builder

SPACING RULES
- minimal vertical spacing
- no empty sections
- tight layout
- prioritize readability
- if a section uses 3 columns, keep complete rows of 3 cards only

MOBILE-FIRST RULES
- stacked layout
- short sections
- easy tap targets
- collapsible FAQs if needed

DESKTOP RULES
- readable line length
- centered or balanced layout
- no orphan cards

VALIDATION CHECKLIST
Before publishing:
- title equals OG title and Twitter title
- meta description equals OG description and Twitter description
- H1 aligns with title
- schema name does not contain "|"
- schema description equals meta description
- canonical and hreflang URLs are correct
- raw EN/ES links exist in source HTML
- JSON-LD parses cleanly
- no empty href values
- no generic OG placeholder image when a page image exists
- no TODO, FIXME, undefined, or broken typo strings
- layout keeps complete card rows
- page ends with valid closing body and html tags
