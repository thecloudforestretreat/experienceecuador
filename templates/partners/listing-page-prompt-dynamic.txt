These rules are the source of truth. Ignore older conflicting instructions.

CORE GOAL
Generate standalone recommendation member pages that behave like SEO landing pages, not thin directory listings.

Every page must:
- preserve the global header/footer include system using /assets/includes/header.html and /assets/includes/footer.html
- use SEO-specific meta fields
- use clean bilingual hreflang
- include strong schema
- include analytics attributes
- adapt content blocks to the listing's actual strengths
- avoid false claims and keyword stuffing
- avoid generic one-size-fits-all copy
- build enough authority content that the page can rank for multiple relevant long-tail search intents

GLOBAL HEADER AND FOOTER INCLUDE RULES
Every generated listing page MUST use the shared Experience Ecuador global includes.

Required mount points:
EN:
<div id="siteHeader" data-current-lang="en"></div>

ES:
<div id="siteHeader" data-current-lang="es"></div>

Immediately after </main>:
<div id="siteFooter"></div>

Every page MUST include this injection script after #siteFooter and before page-specific JavaScript:

<script>
  (function(){
    async function inject(id, url){
      var el = document.getElementById(id);
      if(!el) return;
      var res = await fetch(url, { cache: "no-store" });
      el.innerHTML = await res.text();
    }
    Promise.all([
      inject("siteHeader", "/assets/includes/header.html"),
      inject("siteFooter", "/assets/includes/footer.html")
    ]).then(function(){
      if (!document.querySelector('script[src="/assets/js/site.js"]')) {
        var s = document.createElement("script");
        s.src = "/assets/js/site.js";
        document.body.appendChild(s);
      }
    });
  })();
</script>

Rules:
- Do not hardcode page-level header markup.
- Do not hardcode page-level footer markup.
- Do not use header-es.html or footer-es.html.
- Keep the rawLangLinks language switch directly after #siteHeader.
- Keep /assets/css/header.css, /assets/css/footer.css, /assets/css/site.css, and /assets/css/listing-member-seo.css in the head.
- Load /assets/js/site.js only after the shared header and footer are injected.

SEO FIELD RULES
Use:
- META_TITLE_EN -> <title>, og:title, twitter:title, WebPage schema name
- META_TITLE_ES -> <title>, og:title, twitter:title, WebPage schema name
- META_DESCRIPTION_EN -> meta description, og:description, twitter:description, WebPage schema description
- META_DESCRIPTION_ES -> meta description, og:description, twitter:description, WebPage schema description

Do not replace meta titles with TITLE_EN or TITLE_ES.
Do not append "| Experience Ecuador" unless already provided.
UI fields TITLE_EN and TITLE_ES are used for H1, breadcrumbs, CTAs, and labels.
Do not use "best", "top", or "number one" unless explicitly justified by data.

MANDATORY SEO EXPANSION RULES
For every listing page, include at least 2 SEO expansion sections beyond the short description:
- one "where to stay / where to eat / what to do / how to choose" section based on category
- one decision-stage section that helps the traveler compare options or understand fit

For lodging pages, strongly prefer:
- Where to stay in LOCATION
- How to choose lodging in LOCATION
- Staying in ENTITY_OR_NEIGHBORHOOD
- Things to know before booking

These sections must:
- be factual
- avoid hype
- include natural keyword layering
- include internal links where useful
- answer traveler decision questions
- not invent amenities, addresses, pricing, or claims

LODGING VISUAL AUTHORITY RULE
For lodging listings:
- Always treat the page as high visual intent.
- Always use a rich carousel-style gallery in the hero.
- Always include a narrative photo gallery section.
- Do not downgrade lodging pages to a plain static image grid without captions.
- Each image must include descriptive alt text and contextual caption.
- Captions should explain travel meaning, setting, architecture, room feel, nearby context, or guest-use relevance.
- Preserve the provided image URLs exactly.
- Do not invent amenities shown in photos.

MAP RULES
1. IF google_maps_embed_url exists:
- Render a live iframe map preview.
- Also include an "Open map" button if google_maps_share_url exists.
- Use iframe only when the URL is a true Google Maps embed URL.
- Never use a maps.app.goo.gl share URL inside an iframe.

2. IF only google_maps_share_url exists:
- Do not render iframe.
- Render a clickable map card linking to Google Maps.

3. IF only latitude + longitude exist:
- Generate link: https://www.google.com/maps/search/?api=1&query=LAT,LNG
- Render clickable map/location card.
- Do not render iframe.

4. IF no map data exists:
- Do not render .mapSplit or .mapCard.
- Render a full-width location guidance section.
- Include region, destination, arrival note, contact instruction, and CTAs if available.

5. Never show empty iframe, broken map, blank map card, placeholder, invented coordinates, or fake map content.

6. Schema GeoCoordinates only when latitude and longitude are provided.
