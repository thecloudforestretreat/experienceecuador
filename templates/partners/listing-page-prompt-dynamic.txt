DYNAMIC MASTER RULES FOR EXPERIENCE ECUADOR LISTING DETAIL PAGE GENERATION

Use these master templates:
- listing-detail-en-map-ready-SEO-lang-analytics.txt
- listing-detail-es-map-ready-SEO-lang-analytics.txt

Use this shared CSS:
- /assets/css/listing-member-seo.css

These rules are the source of truth. Ignore older conflicting instructions.

CORE GOAL

Generate standalone recommendation member pages that behave like SEO landing pages, not thin directory listings.

Every page must:
- preserve the global header/footer include system
- use SEO-specific meta fields
- use clean bilingual hreflang
- include strong schema
- include analytics attributes
- adapt content blocks to the listing's actual strengths
- avoid false claims and keyword stuffing
- avoid generic one-size-fits-all copy

SEO FIELD RULES

1. Use:
   {{META_TITLE_EN}} -> <title>, og:title, twitter:title, WebPage schema name
   {{META_TITLE_ES}} -> <title>, og:title, twitter:title, WebPage schema name
   {{META_DESCRIPTION_EN}} -> meta description, og:description, twitter:description, WebPage schema description
   {{META_DESCRIPTION_ES}} -> meta description, og:description, twitter:description, WebPage schema description

2. Do not replace meta titles with {{TITLE_EN}} or {{TITLE_ES}}.

3. Do not append "| Experience Ecuador" unless already provided.

4. UI fields:
   {{TITLE_EN}} / {{TITLE_ES}} are used for H1, breadcrumbs, CTAs, labels, and visible business names.

5. Use readable, honest copy. Do not overclaim with phrases like:
   "best lodge"
   "number one"
   "top rated"
   unless the row explicitly provides proof.

DYNAMIC SECTION RULES

Always include these base sections:
1. Hero
2. Short description
3. SEO paragraph section
4. Why section
5. Experience breakdown
6. Location context
7. Decision guide
8. Entity/topic guide
9. Map and location
10. Nearby section
11. Gallery
12. FAQ
13. Explore more / internal links
14. Final CTA

Then activate these conditional sections:

IF has_birdwatching = true:
- Add a birdwatching value section.
- Mention habitat, timing, ecosystem, and birding traveler intent.
- If entity_highlight exists, explain why that entity matters.
- Link to birdwatching or wildlife pages when available.

IF has_river = true:
- Add a riverside setting / relaxation signal.
- Target phrases like river setting, riverside cabins, peaceful stay, nature stay.

IF has_private_reserve = true:
- Add a private reserve / conservation habitat signal.
- Target phrases like private reserve, cloud forest habitat, nature access.

IF is_remote = true:
- Add quiet escape / away from town positioning.
- Clarify this is good for travelers prioritizing nature over central convenience.

IF is_budget = true:
- Mention practical, rustic, value-conscious travel.
- Do not imply luxury.

IF is_family_friendly = true:
- Mention family fit only if supported by row data.
- Avoid inventing amenities.

IF has_culinary = true:
- Add food/culinary intent section.
- Link to culinary experience pages when available.

IF has_waterfalls = true:
- Add waterfall / nature route section.
- Link to nearby destination guides where appropriate.

IF has_adventure = true:
- Add adventure planning section.
- Mention activity type honestly based on row data.

IF no special feature exists:
- Use location, category, traveler fit, and nearby context as the differentiator.

INTERNAL LINKING RULES

Each page should include contextual links to:
- region page
- location page
- category or recommendations page
- relevant experience page
- relevant guide/article page if available
- filtered recommendations page for same region/location/category/experience

Links must use:
data-analytics-event="internal_link_click"
data-analytics-location="<section_name>"
data-analytics-page-type="member"

Avoid excessive links. Use 5 to 10 high-quality internal links per page.

ANALYTICS RULES

Use these event names:
- page_view_enhanced
- language_switch_click
- internal_link_click
- member_gallery_click
- member_external_website_click
- member_whatsapp_click
- member_cta_click

- faq_expand

Required attributes on important links:
- data-analytics-event
- data-analytics-label
- data-analytics-location
- data-analytics-page-type="member"

Recommended section attributes:
- data-analytics-section="seo_context"
- data-analytics-section="decision"
- data-analytics-section="entity"
- data-analytics-section="map"
- data-analytics-section="faq"

LANGUAGE SWITCH RULES

Immediately after #siteHeader:

English:
<div id="siteHeader" data-current-lang="en"></div>
<nav class="rawLangLinks" aria-label="Language switch">

Spanish:
<div id="siteHeader" data-current-lang="es"></div>
<nav class="rawLangLinks" aria-label="Selector de idioma">

Each link must include:
- href
- lang
- hreflang
- aria-current only on active language
- data-analytics-event="language_switch_click"
- data-analytics-target-language

The switch is visually left aligned through listing-member-seo.css.

MAP RULES

If google_maps_embed_url exists:
- Render a live iframe map preview.
- Also include a button to google_maps_share_url if present.

If only google_maps_share_url exists:
- Render a map card that links to Google Maps.

If latitude and longitude exist:
- Add GeoCoordinates to LodgingBusiness schema.

If no map data exists:
- Render location context without an iframe.

SCHEMA RULES

Use:
- WebPage
- BreadcrumbList
- LodgingBusiness for lodging
- Restaurant for restaurants
- LocalBusiness for services/activities
- FAQPage
- TouristDestination when page has location context
- ItemList for related links
- Article for decision-guide content

Add when available:
- dateModified
- geo latitude/longitude
- sameAs
- telephone
- image array

SPANISH RULES

Use natural Latin American Spanish.
Use accents in visible copy and metadata.
Do not use accents in URLs, slugs, IDs, query parameters, or data attribute names.

Correct examples:
- región
- ubicación
- Galería
- Qué hacer cerca
- Por qué hospedarse aquí
- Planifica tu estadía
- relajación

Technical slug:
- relaxation -> relajacion

QA BEFORE HANDOFF

- hreflang/canonical are correct
- live map renders if embed URL exists
- analytics are present
- Spanish visible accents are correct
- no accented technical URLs or data attributes
- no unsupported ranking claims
- schema validates logically
- mobile grids collapse correctly
