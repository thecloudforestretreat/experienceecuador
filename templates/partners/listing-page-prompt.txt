UPDATED MASTER RULES FOR LISTING DETAIL PAGE GENERATION

Use the updated master templates:
- listing-detail-en-map-ready-SEO-lang-analytics.txt
- listing-detail-es-map-ready-SEO-lang-analytics.txt

These rules are the source of truth. Do not use older template names or older conflicting instructions.

SEO MAXIMIZATION

1. Use the row values exactly for:
   - {{META_TITLE_EN}} -> <title>, og:title, twitter:title, WebPage schema name
   - {{META_TITLE_ES}} -> <title>, og:title, twitter:title, WebPage schema name
   - {{META_DESCRIPTION_EN}} -> meta description, og:description, twitter:description, WebPage schema description
   - {{META_DESCRIPTION_ES}} -> meta description, og:description, twitter:description, WebPage schema description

2. Do not replace meta titles with {{TITLE_EN}} or {{TITLE_ES}}.

3. Do not append "| Experience Ecuador" to OG or Twitter titles unless it is already included in the provided meta title field.

4. Keep UI titles short:
   - Use {{TITLE_EN}} and {{TITLE_ES}} for H1, breadcrumbs, CTAs, member labels, and page-visible business names.
   - Use {{META_TITLE_EN}} and {{META_TITLE_ES}} only for SEO title fields and WebPage schema name.

5. Use SEO paragraphs, headings, FAQ, nearby content, image alt text, image captions, and schema fields to reinforce the listing's strongest differentiator.

6. For each listing, prioritize this SEO hierarchy:
   - property / business name
   - category or experience type
   - location
   - unique differentiator

7. Never keyword-stuff. Titles and descriptions must stay readable and click-worthy.

8. Strong examples:
   - Roca Mía | Birdwatching Lodge in Mindo Ecuador with Cock-of-the-Rock
   - Roca Mía | Lodge de Aviturismo en Mindo Ecuador con Gallito de las Rocas
   - Mindo Glambird | Cloud Forest Glamping Lodge in Mindo Ecuador
   - Hacienda Verde Niebla | Coffee Farm Stay in Chocó Andino Ecuador

LANGUAGE SWITCH STANDARD

1. Every generated page must include raw HTML language links immediately after #siteHeader and before main content.

2. English page must use:
   <div id="siteHeader" data-current-lang="en"></div>
   <nav class="rawLangLinks" aria-label="Language switch">

3. Spanish page must use:
   <div id="siteHeader" data-current-lang="es"></div>
   <nav class="rawLangLinks" aria-label="Selector de idioma">

4. Both switch links must include:
   - href
   - lang
   - hreflang
   - correct aria-current only on the active language
   - data-analytics-event="language_switch_click"
   - data-analytics-label
   - data-analytics-location="language_switch"
   - data-analytics-page-type="member"
   - data-analytics-target-language

5. Keep class name exactly:
   rawLangLinks

6. Use shared /assets/css/site.css for switch styling. Do not create page-level language switch CSS.

ANALYTICS STANDARD

1. Use data-* attributes for all important actions.

2. Use only these event names on generated member pages unless explicitly instructed otherwise:
   - page_view_enhanced
   - language_switch_click
   - internal_link_click
   - member_gallery_click
   - member_external_website_click
   - member_whatsapp_click
   - member_cta_click

3. Do not use older one-off names like:
   - listing_detail_view
   - recommendation_click
   - main_cta_click
   - cta_click_primary

4. Website buttons must use:
   data-analytics-event="member_external_website_click"

5. WhatsApp buttons must use:
   data-analytics-event="member_whatsapp_click"

6. Breadcrumb links and Explore More links must use:
   data-analytics-event="internal_link_click"

7. Gallery and carousel controls must use:
   data-analytics-event="member_gallery_click"

8. The body must include:
   - data-page-type="recommendation_member_page"
   - data-page-language="en" or data-page-language="es"

HEADER, FOOTER, AND JS INJECTION

1. Use the inline fetch injection pattern already present in the master templates.

2. Do not use /assets/js/includes.js.

3. Do not hardcode header or footer HTML.

4. Do not modify header/footer structure.

5. Use:
   - <div id="siteHeader" data-current-lang="en"></div> on English pages
   - <div id="siteHeader" data-current-lang="es"></div> on Spanish pages
   - <div id="siteFooter"></div> before the injection script

6. Use Promise.all to inject header and footer.

7. Load /assets/js/site.js only after injection completes, and also in the catch fallback if injection fails.

8. Do not duplicate the site.js loader.

SPANISH AND ACCENT RULES

1. Spanish pages must use natural Latin American / South American Spanish, not Spain Spanish.

2. Spanish visible copy and metadata must use proper accents.

3. Proper names must keep their real accents on both English and Spanish pages.

4. Keep URLs, slugs, asset paths, IDs, and technical fields unaccented unless intentionally accented.

5. Spanish labels must use accents where required:
   - Galería
   - Descripción
   - Qué hacer cerca
   - Ver más
   - región
   - ubicación
   - Por qué hospedarse aquí
   - Planifica tu estadía

6. Do not strip accents from Spanish output. Accent correctness is more important than ASCII-only rendering for visible copy and metadata.

PLACEHOLDER AND QA RULES

1. Fill placeholders only. Do not rewrite layout, rename classes, remove sections, or simplify scripts.

2. No unresolved placeholder tokens may remain in the final HTML.

3. All image alt text, carousel captions, and gallery captions must be replaced in both languages.

4. Keep pipe-separated highlight and best-for values split into exactly 4 bullets each.

5. Normalize phone numbers with a leading + in rendered page text and schema when the source phone lacks one.

6. Before handoff, verify:
   - SEO title and meta description
   - OG/Twitter title and description
   - WebPage schema name and description
   - raw language switch placement
   - language switch hreflang and analytics
   - CTA analytics
   - breadcrumb and Explore More analytics
   - Spanish accents
   - canonical and hreflang links
   - final paths
   - no unresolved placeholders

OUTPUT

Generate two complete files:
- English final file path: /recommendations/members/<region_id_en>/<location_id_en>/<listing_slug>/index.html
- Spanish final file path: /es/recomendados/miembros/<region_id_es>/<location_id_es>/<listing_slug>/index.html

Do not modify layout or structure.

- restaurants -> Restaurant
- services -> LocalBusiness

- Concise second supporting sentence.
- Should reinforce the unique differentiator without repeating the first paragraph.

SPANISH EXPERIENCE FILTER SLUGS

When generating Spanish text labels, use natural Spanish labels:
- wildlife-birding -> aviturismo / vida silvestre
- adventure -> aventura
- culinary -> gastronomía
- relaxation -> relajación
- nature -> naturaleza

Do not use "relax" as the Spanish label or slug for relaxation. Use "relajación" in visible Spanish copy and "relajacion" in technical slugs when needed.
